# MiSTer NES core on the Chromatic (GW5A-25): synthesis feasibility probe

Upstream: https://github.com/MiSTer-devel/NES_MiSTer at `cf7fe6c` (2026-11-16, see `REVISION`).
Device: GW5A-EV25UG256CC1/I0 version A (23,040 logic, 56 BSRAM, 28 DSP), Gowin EDA V1.9.12.04, `run syn` only.
Nothing was programmed. The clone in `NES_MiSTer/` is unmodified. Patched copies are generated into `syn/src/`.

## 1. Results

Top = `NES` (nes.v) in a thin wrapper (`syn/nes_probe_top.sv`). Savestates are on. The SDRAM side (PRG/CHR ROM, CHR RAM, CPU RAM, VRAM, cart RAM) and the savestate DDR bus are top-level ports, so they are not synthesized. Tied off as a Chromatic build would be: NTSC only (sys_type 0, so no PAL, Dendy or Vs. logic), no FDS, no expansion audio, no Game Genie, no extra sprites, no composite video, no debug dots. In the "full" mapper set, the FME-7 (69) is built without its Sunsoft 5B audio.

| Build | Mappers | Logic (LUT+ALU) | LUT | ALU | FF | BSRAM | DSP | Syn Fmax est. |
|---|---|---|---|---|---|---|---|---|
| **stock, full** | 0,1,2,3,4,7 + 9,10,11,66,69,71,21-25 | **16,262 (71%)** | 16,086 | 176 | 5,482 | 0 | 0 | 64.5 MHz |
| **stock, small** | 0,1,2,3,4,7 | **15,745 (68%)** | 15,569 | 176 | 5,156 | 0 | 0 | 62.8 MHz |
| OAM in BSRAM, full | same as full | 7,721 (34%) | 7,545 | 176 | 3,421 | 1 | 0 | 66.1 MHz |
| OAM in BSRAM, small | same as small | 7,144 (31%) | 6,969 | 175 | 3,095 | 1 | 0 | 63.1 MHz |

"Mapper" here means the iNES numbers. They are handled by these modules: 0/2/3/7 by `Mapper28`, 1 by `MMC1`, 4 by `MMC3`, 9 by `MMC2`, 10 by `MMC4`, 11/66 by `Mapper66`, 69 by `Mapper69`, 71 by `Mapper71`, and 21/22/23/25 by `VRC24`.

**The stock core does not fit the 12-13k budget (it needs about 16k), and the mappers are not the reason.** One module dominates: `OAMEval` in ppu.sv is 8.9-9.0k LUT and 2,370 FF, more than half the core. It keeps the 256-byte OAM and the 64-byte secondary OAM in flip-flops. Several things prevent block-RAM inference:
- an 8-byte-per-cycle OAM row copy (emulation of OAM corruption when rendering starts),
- extra-sprite evaluation that reads up to 4 OAM bytes per cycle,
- a sprite-repeat check that reads 3 OAM bytes per cycle,
- a separate savestate write port,
- an array reset of the secondary OAM.

The "OAM in BSRAM" rows use an experimental rewrite, generated by `tools/prep.py` into `src/ppu_oam.sv`. It has one shared read/write port with a registered read (the savestate port is muxed in), no extra-sprite or repeat logic, no row-corruption emulation, and a 32-byte secondary OAM. `OAMEval` drops to about 420 LUT, 310 FF and 1 BSRAM, and the whole core lands at **7.1-7.7k logic**. **This rewrite has not been checked cycle by cycle.** The registered read shifts OAM read timing by one master clock and has to be verified in simulation (blargg sprite/OAM tests, oam_read, oam_stress, sprite-0 hit tests) before anyone trusts it.

The Fmax figures are GowinSynthesis estimates for single-cycle paths at the default 100 MHz constraint. They are pre-place-and-route and optimistic. The worst path is inside T65 (`PC` to `BAL`, 19-21 logic levels). In the real design, every NES flip-flop only needs to settle within one *master* clock (46.6 ns), and the CPU paths are enabled once per 12 master clocks. See the clocking risk in section 4.

### Things Gowin needed (all in `syn/tools/prep.py`; the clone is untouched)

1. `import regs_savestates::*;` in every file that uses `SSREG_*`. Quartus leaks the import from ppu.sv into the compilation unit.
2. `always begin` changed to `always @* begin` (Quartus infers combinational logic).
3. 64 procedural assignments to `wire` or plain `output` nets became `logic` (EX3900; list in `tools/decl_fixes.txt`).
4. **A trap:** the RTL uses many nets before their declaration (`color0`, `apu_cs`, `SaveStateBus_*`, `ppu_dbus`, the mapper `prg_aout`/`chr_aout` ...). Gowin silently turns the early use into an undriven 1-bit implicit net (warning EX1998 only). The first successful run had `color` tied to GND and reported 10.7k LUT. The script hoists about 300 such declarations, and the numbers above are after that fix. Any port must keep this pass, or carry it as a source patch, and check EX1998/EX3638 warnings on every build.
5. The cart's `tri0`/`tri1` mapper buses synthesize, but 24 bits reached the top-level ports as TBUFs (no mapper enabled means Z). In the real build, replace them with explicit AND-OR merges.
6. No Intel primitives remain. The NES module itself has no altsyncram; only `sdram.sv` (altddio), `dpram.vhd` and the NES.sv top used them, and none of those are built. VHDL (T65, savestates) is read natively by GowinSynthesis, with no GHDL needed.

## 2. Interface inventory (from the rtl)

### (a) Memory interface of nes.v

The core has no on-chip RAM except OAM (and palette registers). Everything else goes out through two byte-wide ports into one SDRAM:

- **CPU port:** `cpumem_addr[24:0]`, `cpumem_read`, `cpumem_write`, `cpumem_dout`, `cpumem_din`.
- **PPU port:** `ppumem_addr[21:0]`, `ppumem_read`, `ppumem_write`, `ppumem_dout`, `ppumem_din`.
- Plus `refresh`, and the savestate side port (`Savestate_SDRAM*`).

The linear address map (mapper output after `prg_mask`/`chr_mask`, see cart.sv):

| Region | Linear address | Size | Port |
|---|---|---|---|
| PRG ROM | 0x000000-0x1FFFFF (bit 21=0) | up to 2 MiB | CPU |
| CHR ROM or CHR RAM (`mapper_flags[15]`=CHR RAM, write allowed by `chr_allow`) | 0x200000-0x2FFFFF | up to 1 MiB | PPU |
| CPU internal RAM ($0000-$1FFF, 2 KiB mirrored) | 0x380000-0x3807FF | 2 KiB | CPU |
| CIRAM / nametable VRAM (`vram_ce`, A10 = `vram_a10` from mapper mirroring) | 0x3A0000-0x3A07FF | 2 KiB | PPU |
| Cart RAM: PRG RAM/battery $6000-$7FFF | 0x3C0000+ (MMC1 SXROM up to 32 KiB, MMC3 8 KiB, Mapper28 8 KiB if NES 2.0 says so) | | CPU |
| MMC3 TQROM CHR-RAM / four-screen NT RAM | 0x3FE000 / 0x3FF000 | 8 / 4 KiB | PPU |
| Misc ROM (mapper 413 only) | bit 24 | | CPU |

Strobes are levels. MiSTer's `sdram.sv` starts an access on the **rising edge** of a read or write strobe. `*_din` must **hold the last read byte** until the next access; the core relies on it, and the SDRAM `ch0/ch1_dout` latches are saved in savestate register 28 (`SS_Ext`).

**Timing and slots** (from the clock comment in nes.v and the code). One CPU cycle is 12 master clocks, which is 3 PPU dots.

- **CPU.** The address changes at `cpu_ce` (master clock 12 of the cycle). `prg_read`/`prg_write` are qualified by `cart_pre` (`div_cpu` 6-10), so the CPU's SDRAM request rises at master clock 6. The mapper `cart_ce` is at clock 10. The CPU latches `cpumem_din` at clock 12. So **about 6 master clocks (280 ns) from request to use**, while the address itself is valid about 11 clocks (510 ns) before use.
- **PPU.** The PPU models the multiplexed bus. In the ALE dot the full address is out. `ppumem_read` (= `vram_r`) is high for the following dot, and the data is latched at that dot's `ppu_ce`. So **about 4 master clocks (186 ns) from read strobe to latch**, and about 8 (372 ns) from address-valid. During rendering there is one PPU access every 2 dots (NT, AT, PT-lo, PT-hi per 8 dots, and the same during the sprite fetch in hblank).
- **MiSTer's controller.** SDRAM runs at 85.9 MHz (4x master). Each closed-row access takes 7 clocks (81 ns). The priority is PPU (ch0), then CPU (ch1), then the save/backup channel (ch2). A CPU access waits at most one PPU access (about 163 ns worst case). A repeated read of the same 16-bit word is served from a latch and used as an auto-refresh slot. The core's `refresh` output is only active while paused.
- **Load.** The loader writes the ROM through ch0 while `downloading`.

### (b) Clocking

- `clk` is the **NES master clock itself: 21.477272 MHz** (NTSC; the PAL clock is reconfigured by `pll_cfg`). MiSTer's PLL makes 85.909 MHz (SDRAM), 42.95 MHz (video) and 21.477 MHz (`clk`).
- **nes.v has no master-clock-enable input.** Every `always @(posedge clk)` in nes.v, ppu, apu, cart/mappers and savestates assumes one tick per master clock.
- Internal clock enables:
  - `cpu_ce` once per 12 clocks (1.79 MHz),
  - `ppu_ce` once per 4 (5.37 MHz),
  - `cart_ce` = `div_cpu` 10 (M2),
  - `apu_ce` = `cpu_ce`, with put/get phases,
  - PAL adds one PPU tick per 5 CPU cycles,
  - `freeze_clocks` "de-jitter" inserts a fake pixel on short frames (`dejitter_timing`=0).
- `pausecore` stops the core cleanly: at vblank, on an instruction boundary, with all dividers aligned (`corepaused`). Savestates use this.

### (c) Save states

- **Trigger.** `save_state` / `load_state` pulses plus `savestate_number[1:0]` go to `statemanager`, which returns a slot address: `0x3800000 + slot*0x80000` in 32-bit-word units, so a 2 MiB stride in DDR3. `savestates.vhd` raises `sleep_savestate`. NES.sv turns that into `pausecore`. It then waits for `corepause_active_delay` plus 100 settle clocks.
- **Register phase.** The internal registers travel on the **ss bus**: 10-bit `SaveStateBus_Adr`, 64-bit `Din`/`Dout`, `wren`, `rst`, `load`. Every module has `eReg_SavestateV` instances (64-bit shadow registers, indices in `regs_savestates.sv`: CPU 0-2, PPU 4-12, APU 16-19, TOP 24, EXT 28, mapper 32-37/40, sound 48-52). Readback is a wired-OR of every module's 64-bit `Dout`. Save reads indices 0..63 and writes each to the output bus. Load writes them back, and every module copies `SS_*` into its live registers while `SaveStateBus_load` (`loading_savestate`) is high. Then `reset_ss` pulses.
- **Memory phase.** `Save_RAMAddr/RdEn/WrEn/Data`, routed by `Save_RAMType` (`memory_slow`: one byte per 8 clocks):

| Type | Region | Size |
|---|---|---|
| 0 | OAM | 256 B (in PPU) |
| 1 | MAPPER RAM | 8 KiB (mapper-internal RAMs: MMC5, N163, FDS) |
| 2 | CHR | 1 MiB at 0x200000, **the whole CHR window, ROM included** |
| 3 | VRAM | 2 KiB at 0x3A0000 |
| 4 | CPU RAM | 2 KiB at 0x380000 |
| 5 | CART RAM | 256 KiB at 0x3C0000 |

  Types 2-5 go through the SDRAM ch2 side port (`Savestate_SDRAM*`).
- **Output bus.** `SAVE_out_*`: 64-bit data, 26-bit word address (+2 per 64-bit beat), `rnw`, `ena` (1-cycle pulse), `be`, and a `done` handshake. This is **the same bus signature as the MiSTer Lynx core**, so `lynx_state_engine.sv` (staging the image in PSRAM for the MCU) is a direct template.
- **Image layout.** Header (`STATESIZE`=331,776 words, plus a save counter), then 64 x 8 B registers, then the regions. **About 1.27 MiB per slot**, and about 0.5 s at 8 clocks per byte. Load checks the header size word.

## 3. Memory split recommendation

Keep **all RAM on chip in BSRAM** (a GW5A 18 Kbit block in x8 mode holds 2 KiB), and put **only PRG/CHR ROM in PSRAM** (read-only traffic):

| Region | BSRAM | Note |
|---|---|---|
| OAM 256 B | 1 | inside the core, after the OAMEval rework |
| CPU RAM 2 KiB | 1 | |
| CIRAM 2 KiB | 1 | +2 if MMC3 four-screen (Rad Racer II, Gauntlet) is wanted |
| PRG RAM 8 KiB | 4 | MMC1 SOROM/SXROM 16/32 KiB: treat as unsupported, or put the extra in PSRAM |
| CHR RAM 8 KiB | 4 | needed at the same time as PRG RAM (SNROM: Zelda, FF1). MMC3 TQROM CHR-RAM can share it. |
| **Subtotal** | **11** | |
| PSRAM line cache (PRG and CHR) | 2-4 | gg_rom_bridge style, 2 KiB per block |
| NES palette to RGB (64 colours x 8 emphasis) | 1 | |
| 256-to-160 scaler line buffers | 1-2 | |

That totals **about 15-18 BSRAM**, within the 25-30 target (about 39-42 of 56 with the shell). Turning the APU mixer tables and the palette registers into BSRAM ROMs/RAMs would cost about 2 more blocks and save about 1.2k LUT.

The wrapper routes by linear address: CPU 0x38xxxx goes to CPU RAM, CPU 0x3Cxxxx to PRG RAM, CPU <0x200000 to PSRAM; PPU 0x3Axxxx goes to CIRAM, PPU 0x2xxxxx to CHR RAM if `mapper_flags[15]`, otherwise to PSRAM. During savestates, the `Save_RAM*`/`Savestate_SDRAM*` ports are muxed onto the same BSRAMs. Writes never reach PSRAM in this mapper set.

PSRAM read demand is about one random byte per 280 ns (CPU PRG read about every 559 ns, plus CHR pattern reads about every 745 ns). **Start each fetch when the address becomes valid, not on the strobe.** The address is stable about 510 ns (CPU) and about 372 ns (PPU) before the data is latched; MiSTer's rising-edge scheme only uses 280 ns and 186 ns.

## 4. Risks

1. **OAM rework is mandatory.** Without it, about 16k logic plus 9.65k shell does not fit. The rework drops upstream's OAM-corruption emulation and extra sprites (a non-accurate enhancement anyway). It needs simulation against sprite and OAM test ROMs, and it diverges from an actively changing upstream ppu.sv (last commit 2026-11-16 touched the PPU).
2. **Clocking.** The core expects `clk` = master clock with no clock-enable input. Three options:
   - **(a) Gated clock (preferred).** Feed the NES domain from 67.108864 MHz through a DHCE / clock gate driven by a fractional accumulator. 8 of 25 gives 21.4748 MHz; 0.31951 of xclk gives exactly 60.000 Hz NTSC frames (357,366 master clocks per frame x 60 = 21,441,960 Hz, a 0.16% pitch shift). Edges are at least 3 xclk apart, so a multicycle-3 constraint covers the whole domain and the 63-66 MHz single-cycle estimate does not matter. The same gate can **stall the whole NES on a PSRAM miss** without losing cycle accuracy.
   - **(b)** A separate PLL clock (27 MHz x 35/44 = 21.477272 MHz exactly, if the PLL's VCO range allows), with domain crossings.
   - **(c)** Threading a global CE through about 200 always blocks. Not recommended.
3. **PSRAM latency and contention.** The NES cannot wait natively. MiSTer guarantees completion within about 163 ns. On the Chromatic the PSRAM is shared with the shell (panel ring and the MCU's xVirtual port), so a bounded-latency slot or a cache plus clock-stall is required. This is the main design risk.
4. **Save states:**
   - Upstream dumps 1 MiB of CHR (ROM included) and 256 KiB of cart RAM. Shrink the `savetypes` table in savestates.vhd to the real regions (CHR RAM 8 KiB only if present, PRG RAM 8 KiB, drop the 8 KiB mapper-RAM type for this mapper set). The image becomes **about 21 KiB** (header 8 + regs 512 + OAM 256 + VRAM 2K + CPU 2K + PRG RAM 8K + CHR RAM 8K) instead of 1.27 MiB.
   - The memory-side model must also provide the "last read byte" latches of both ports (`SS_Ext`, register 28).
   - Upstream has a 0x3FE000/0x3FF000 TQROM/four-screen RAM that must be included if those boards are supported.
   - The pause handshake (`pausecore`/`corepaused`) must be honoured by the clock gate.
5. **Gowin front-end quirks** (section 1): forward-referenced nets become silent 1-bit implicit nets. Keep the hoisting pass and watch EX1998/EX3638.
6. **Not yet costed:** glue on the NES side (memory router, PSRAM cache, 256x240 to 160x144 scaler, APU decimation filter, state engine, loader). With the core at about 7.1-7.7k, that leaves about 4.5-5.5k logic in the 12-13k budget.
