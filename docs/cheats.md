# Game Genie selector

This build provides preloaded, per-game Game Genie options for **SD games** without changing FPGA 18.38.

In BACKUPS, show a game’s preview and press **Select**. If the scrolling selector is open, press **A** first to reveal the preview. Use Up/Down to browse, **A** to toggle an option, and **B** to return to the same game. The first item disables all options for that game. Selected descriptions scroll when they are too long for a row. Holding Up/Down repeats and accelerates. The footer reports how many options are enabled and says **NEXT LAUNCH**.

The browser places the original pixel-art lamp with a smoke curl inside the green frame. It uses the lower-right black padding beside the
media when that entire edge is empty; otherwise it sits beside the title.
Neither position covers or resizes the artwork or video. Once a video frame
needs the title position, the lamp stays there for that clip to avoid jitter. An **outlined lamp** means a readable cheat pack is available; a **filled
gold lamp** means at least one option is saved for the next launch. There is no
badge for folders or games without a valid pack. It is hidden while the scrolling
list covers the preview. The badge is cleared immediately on a selection change;
stale worker results cannot attach another game's status. It also remains visible beside
video previews. The cheat menu uses a larger lamp beside its gold wordmark.

Badge lookup checks the pack header, payload integrity, and saved settings on the
background SD worker. It shares an artwork mount when both requests are pending,
uses owned paths/tokens, and reads no ROM data while browsing. The full ROM match
is still checked when opening the cheat selector or launching selected patches.
The filled lamp indicates saved selections, not live effects in an already
running game. Both symbols are original code-native pixel art generated by
`mcu/tools/generate_genie_lamp.py`.

Launch the game again to apply changes. Automatic last-game startup uses the same selections. This is a restart, not a live toggle or a save-state resume. Turning a cheat off does not reverse changes already recorded in a normal game save. Physical cartridge games are unaffected.

All cheats default off. Selections are stored in MCU NVS settings per ROM CRC, with ROM size and cheat-pack checksum binding. Changing a pack defaults its selections off, preventing old selection indices from enabling different codes. No browsing writes or repeated writes for unchanged settings occur. Toggle settings are committed only after the pack read and SD cleanup succeed. NVS/SD errors are displayed rather than reported as successful toggles.

## Database source

No database or prebuilt cheat packs are bundled in this repository. Generate packs for your own ROMs using the compiler below. A missing match displays **NO GAME GENIE CHEATS FOR THIS GAME**; coverage depends on your exact games and revisions.

The preparation workflow uses [libretro/libretro-database](https://github.com/libretro/libretro-database), revision `6099988fec4c52a4a7294a619795f4b983cf6bb1`. The compiler copies its license and writes attribution into the output directory; keep those files with any generated packs. Packs contain descriptions and sparse patches, not complete ROMs, saves, box art, or video.

The compiler uses exact normalized titles, region sets and revision tags from explicitly labeled Game Genie files. It ignores only hardware-description tags (SGB Enhanced, GB Compatible, Rumble Version). It does not guess matches between USA/Europe/World releases or between revisions. It checks comparison bytes against the supplied ROM and binds the output to the ROM's size and full CRC32. This prevents applying a generated pack to a different ROM; it does not prove that every community-authored cheat works. Actual gameplay testing remains necessary.

Six- and nine-digit Game Genie ROM codes are supported. Grouped codes remain one toggle. Each option is compiled to physical ROM byte patches; comparison-byte checks, header protection and bank mapping checks run during preparation. Codes needing live on/off switching, unsupported formats/mappers, large or multicart MBC1 arrangements, and ambiguous MBC5 bank-zero aliases are excluded. These exclusions are recorded in the preparation report. GameShark and Pro Action Replay are not supported by this MCU-only implementation.

## Install data

After building packs below, copy the generated **CHEATS** folder into the SD card's existing **CHROMAGIC** folder. Keep the matching directory tree, for example:

```
CHROMAGIC/BACKUPS/GB/S-Z/Super Mario Land (World).gb
CHROMAGIC/CHEATS/GB/S-Z/Super Mario Land (World).gb.cmc
```

Firmware alone does not include the database. Existing games, artwork and previews need no changes.

## Build packs for another library

Use an empty staging destination. Obtain the database revision above and provide your own ROM collection:

```sh
python3 mcu/tools/prepare_cheats.py \
  --rom-root /path/to/CHROMAGIC/BACKUPS \
  --database /path/to/libretro-database \
  --output /path/to/staging/CHROMAGIC/CHEATS \
  --report /path/to/staging/cheat-report.json
```

The report lists exact source files, ROM and pack SHA-256 hashes, exclusions, and coverage. Retain the database attribution/license with redistributions. CRC32 is an integrity/identity check, not a cryptographic signature; install packs from a trusted source.

## Implementation and validation

The background browser worker serializes cheat reads with cover/video requests and closes the preview stream before mounting the SD card. UI snapshots own their text; no LVGL work runs on the SD worker. Only three descriptions are held in the UI. Packs allow up to 256 options; a launch allows up to 512 physical byte patches. Conflicting enabled replacements are rejected before saving selections.

Before changing the running game, the loader validates the selected pack and full ROM CRC and prepares a bounded patch plan. It patches transfer buffers while uploading to PSRAM; it never modifies the original ROM file or FPGA. It checks original bytes before changing each block. ROM checksum diagnostics continue to use original, unpatched bytes. Boot/header bytes are protected.

The 24-test host suite covers the compiler's known decoding vectors, bank comparison and ambiguity rejection, revision/region matching, live-toggle filtering, binary integrity, corrupted settings, persistence, conflicts, failed commits/unmounts, loader patching with unchanged source files, asynchronous worker cancellation, menu routing and rendering, and the real Select-button receive/edge path. Host tests do not establish every cheat's gameplay behavior.

An on-device art25 check confirmed the selector opens and **Invincible**
works in **Super Mario Land (World)**. The loader console confirms one ROM patch
and successful gameplay startup. This does not verify other database entries.
